The problem

A dependency is drowning.
Turn the load down.

When the database behind your reports page starts to fall over, the fix in the moment is to stop sending it traffic. Usually that means a config change and a redeploy, in the middle of an incident. brownout lets you shed that one route right now, then lift the rule when the incident is over.

  • {% include ".icons/material/check-decagram-outline.svg" %} Takes effect on the next request: rules are swapped atomically
  • {% include ".icons/material/check-decagram-outline.svg" %} Shed all of a route, or let a set percentage of it through
  • {% include ".icons/material/check-decagram-outline.svg" %} Rules with a TTL lift by themselves, so a forgotten brownout can't outlast the incident

Core ideas

One small rule.
Three decisions.

A rule says which requests it matches, how many of them to let through, and when to stop applying. Rules are checked in order, and the first match decides.

Match

path and method

An exact path, a prefix ending in *, or * for everything, optionally limited to some methods.

{"path": "/api/*",
 "methods": ["POST", "DELETE"]}

Let some through

partial brownouts

The default sheds everything. Set a percentage to cut load without switching the feature off.

{"path": "/search",
 "allow_percent": 20}

Expire

self-healing

Give a rule a TTL through the admin API, or an ExpiresAt in Go, and it lifts by itself.

{"path": "/reports/*",
 "ttl": "10m"}

Quick start

Wire it in
in three steps.

You need Go 1.24 or newer and an existing http.Handler.

{% include ".icons/material/book-open-page-variant-outline.svg" %} Full getting-started guide

  1. Install

    $ {{ install }}

  2. Wrap your app

    Serve the admin API on an internal-only listener.

    c := brownout.New()
go http.ListenAndServe(":8080", c.Middleware(app))
http.ListenAndServe("127.0.0.1:9090", c.AdminHandler())

  3. Brown out a route

    Shed /reports/* for ten minutes.

    $ curl -X PUT localhost:9090/rules/reports -d '{"path":"/reports/*","ttl":"10m"}'
